# 프레스 유압펌프 이상 탐지 웹앱

제출 코드(`새 폴더/제출/소스코드/`)의 하이브리드 이상 탐지 모델(모양 탐지기 + 크기 탐지기)을
웹에서 시연하는 로컬 Streamlit 앱입니다. 제출 코드 파일은 수정하지 않고 그대로 import해서 씁니다.

## 1. 실행 방법

```bash
cd web_app
C:\Users\doon2\AppData\Local\Programs\Python\Python313\python.exe -m pip install -r requirements.txt
C:\Users\doon2\AppData\Local\Programs\Python\Python313\python.exe -m streamlit run app.py
```

(일반 `python` 명령은 이 환경에서 스토어 스텁이라 실패하므로 위 전체 경로를 써야 합니다.)

실행하면 브라우저가 자동으로 열리고(안 열리면 `http://localhost:8501` 접속), 모델은 **앱이 처음 켜질 때
한 번만** 학습·캐시됩니다(제출 코드와 동일한 절차: 정상 학습 사이클로 학습, 정상 검증 99.5 백분위수로 임곗값).

## 2. 폴더 구성

```
web_app/
├─ app.py                 Streamlit 메인 화면
├─ pdm_app/
│  ├─ model_service.py    제출 코드 import + 학습/보정 캐시
│  ├─ loader.py           업로드 CSV 검증·전처리 (제출 코드의 load() 규칙 재현)
│  ├─ data_quality.py     센서·기록 품질 점검 (결측/고착/물리적으로 불가능한 값/시각역행/샘플링)
│  ├─ judge.py            정상/센서점검/이상 판정 로직 + 파일 단위 기준
│  └─ samples.py          내장 샘플 경로 + 센서 오류 합성 샘플 생성
├─ vendor/                배포용 자기완결 사본 (아래 3절 참고)
│  ├─ pdm_hybrid.py, experiment.py   제출/소스코드와 바이트 단위로 동일한 복사본
│  └─ data/               press_data_normal.csv, outlier_data.csv 복사본
└─ requirements.txt
```

## 3. vendor/ 폴더와 배포

`새 폴더/제출/소스코드/`는 그대로 두고(수정 금지), 그 안의 `pdm_hybrid.py`·`experiment.py`와
`data/` 두 CSV만 **복사**해서 `web_app/vendor/`에 넣어 뒀습니다. `pdm_app/model_service.py`와
`pdm_app/samples.py`는 `vendor/`가 있으면 그것을 우선 사용하고, 없으면 원래 경로
(`새 폴더/제출/소스코드/`)로 자동 대체합니다 — 그래서 `web_app/` 폴더 하나만 떼어가도
(예: GitHub 저장소로 푸시) 앱이 그대로 동작합니다. `vendor/` 안의 두 `.py` 파일은 독자적으로
수정하지 않고, 원본(`제출/소스코드/`)이 바뀌면 그대로 다시 복사해 동기화합니다.

### Streamlit Community Cloud 배포

1. [share.streamlit.io](https://share.streamlit.io)에 GitHub 계정으로 로그인
2. "New app" → 이 저장소 선택, **Main file path**: `app.py` (저장소 루트가 `web_app/` 내용이면)
   또는 저장소 루트가 상위 폴더라면 `web_app/app.py`
3. Python 버전은 3.11 또는 3.12 선택 (3.13은 아직 미지원일 수 있음)
4. `requirements.txt`는 같은 폴더에서 자동 인식됩니다
5. Deploy 클릭 — 처음 로딩 시 모델 학습(수 초)이 한 번 일어난 뒤 대시보드가 뜹니다
```

제출 코드 경로(`../제출/소스코드`)를 `sys.path`에 추가해서 `pdm_hybrid.py`, `experiment.py`를
그대로 import합니다. 원본 데이터도 `제출/소스코드/data/`에 있는 파일을 그대로 읽습니다(복사하지 않음).

## 3. 모델 사용 방식

- `experiment.prepare()`를 그대로 호출해 제출 코드와 동일하게 로드 → 사이클 추출 → burst 시간블록
  분할 → `HybridDetector` 학습(정상 학습 사이클로 학습, 정상 검증 사이클 99.5 백분위수로 임곗값)까지
  수행하고, `st.cache_resource`로 캐시해 앱 재실행 시 다시 학습하지 않습니다.
- **이상 확률(anomaly_prob)**: 위험지수(`risk_index`)에 로지스틱 회귀(Platt 보정)를 적용합니다.
  학습 데이터 = 정상 검증 사이클(label 0) + **내장 이상 샘플 전체**(label 1), 앱 시작 시 1회 학습.
  이 보정기는 내장 이상 샘플을 "본" 상태로 학습되므로, 화면 하단에
  "⚠ 이 보정은 내장 이상 샘플을 학습에 사용했으므로…"라고 항상 표시합니다.
- 업로드 CSV는 `pdm_hybrid.load()`와 동일한 규칙(중복 시각 제거 → 0.2초 초과 간격에서 burst 분할 →
  전류 봉우리 기준 사이클 추출)을 거쳐 모델에 들어갑니다. `Equipment_state` 컬럼이 있으면 정답
  비교(혼동행렬)에만 쓰고 판정에는 쓰지 않습니다.

## 4. 상태 판정 규칙과 근거 수치

우선순위: **이상 > 센서 점검 필요 > 정상**(둘 다 걸리면 메인은 "이상 발생", 센서 문제는 보조 경고).

### 4-1. 파일 단위 "이상 발생" 기준

경보 사이클 비율 또는 경보 burst 비율이 **5%를 넘으면** "이상 발생"으로 판정합니다.

| 구분 | 경보 사이클 비율 | 경보 burst 비율 |
|---|---:|---:|
| 정상 파일 전체 (756사이클/530burst, 학습에 쓴 구간 포함) | 0.40% (3/756) | 0.57% (3/530) |
| 이상 파일 전체 (30사이클/17burst) | 100% (30/30) | 100% (17/17) |

(이 수치는 `pdm_app/model_service.py`의 `get_pipeline()`이 앱 시작 시 직접 측정해서
`baseline` 딕셔너리로 반환하고, 정상 샘플 화면에도 참고용으로 표시합니다.) 두 값의 차이가 매우 커서
5%는 정상 파일 기준치의 약 9~12배, 이상 파일 기준치의 1/20 수준으로 안전 마진을 크게 두고 정했습니다.
기준은 `pdm_app/judge.py`의 `ANOMALY_CYCLE_RATIO_THRESH` / `ANOMALY_BURST_RATIO_THRESH`에 있습니다.

### 4-2. "센서 점검 필요" 기준

아래 중 하나라도 있으면 센서 점검 필요로 판정합니다 (`pdm_app/data_quality.py`):

1. 결측값 · 숫자로 읽을 수 없는 값
2. 같은 값이 **5행 이상** 연속되는 고착/포화 구간
3. **물리적으로 불가능한 수준의 고립된 값**: 정상 파일과 이상 파일 모두에서 관찰된 값의 범위
   (`AI0/AI1_Vibration`: 최대 |1.8|, `AI2_Current`: 최대 |539|)보다 훨씬 큰 경계
   (`AI0/AI1`: |값|>5.0, `AI2`: |값|>2000, 즉 이상 파일 최댓값의 약 3~4배)를 넘는 값이 **3행 이하로
   고립**되어 나타날 때만 해당. "정상 범위 밖"이라는 것만으로는 센서 오류로 보지 않습니다 —
   실제로 `data_check.py`를 돌려보면 이상 파일도 값 이상치(|z|>6) 153+21건, 튀는 값(차분 |z|>6)
   65+2건이 나오는데(정상 범위를 넓게 벗어나지만 연속적으로 변하는 진짜 이상 신호이기 때문), 이런
   z-점수나 "정상 범위 밖" 기준만 쓰면 이상 샘플 자체가 전부 센서 오류로 오판됩니다. 그래서 더 넓은
   절대 경계 + 고립성 조건을 함께 요구합니다.
4. 시각 역행, 또는 같은 시각이 **2행 이상** 중복(※ 정상 파일 자체에 이미 알려진 중복 1건이 있어
   —README 3절—1건만으로는 잡지 않습니다)
5. burst 안 샘플링 간격이 10Hz(0.1초)와 크게 다름 (0.09~0.11초 비율이 50% 미만)

### 4-3. 권고 조치

- 이상 발생 + 모양 경보 우세 → "전기·구동·부하 계통 우선 점검"
- 이상 발생 + 크기 경보 우세 → "펌프 체결·베어링 등 기계 계통 우선 점검"
- 센서 점검 필요 → 발견된 문제 중 첫 번째 항목을 안내

## 5. 내장 샘플

| 샘플 | 내용 | 기대 판정 |
|---|---|---|
| 정상 데이터(normal) | `press_data_normal.csv` 원본 그대로 (20,000행) | 정상 작동 |
| 이상 데이터(outlier) | `outlier_data.csv` 원본 그대로 (600행, 30사이클) | 이상 발생 |
| 센서 오류 예시 | 정상 데이터 앞 2,000행에 결측 18개, 고착 9행, 물리적으로 불가능한 고립 스파이크 2개,
  시각 역행 1곳을 **인위로 주입한 합성 데이터** (`pdm_app/samples.py`, 고정 시드) | 센서 점검 필요 |

센서 오류 예시는 물리적으로 불가능한 스파이크가 있는 두 행을 같은 행의 다른 센서 컬럼도 함께
결측 처리해서, 그 행 전체가 모델 입력(사이클 추출)에서는 제외되게 설계했습니다. 그렇지 않으면
극단값이 사이클 특징에 섞여 모델도 함께 "이상 발생"으로 경보하게 되고, 그러면 우선순위 규칙상
메인 상태가 "이상 발생"이 되어 센서 오류 예시의 취지(순수 데이터 품질 문제 시연)가 흐려집니다.
화면에는 항상 "⚗ 합성 예시"라고 표시됩니다.

## 6. 검증 결과

다음을 직접 실행해 확인했습니다 (2026-10-06):

- 내장 정상 → **정상 작동**, 내장 이상 → **이상 발생**, 센서 오류 예시 → **센서 점검 필요**
- 정상 데이터 앞 3,000행 CSV 업로드 → **정상 작동**, 이상 데이터 CSV 업로드 → **이상 발생**

  (10행 CSV는 부분 사이클 1개가 만들어져 "정상 작동"으로 정상 처리됨)
- 제출 폴더(`새 폴더/제출/`) 소스 코드·데이터 파일은 변경하지 않았습니다. 다만 개발 중 참고용으로
  `제출/소스코드/data_check.py`를 1회 직접 실행해서 `제출/소스코드/results/data_quality.csv`가
  재생성되었습니다(코드는 결정적이라 내용은 기존과 동일하고 수정 시각만 바뀜 — 그 외 제출 폴더
  파일은 전혀 건드리지 않았습니다).

## 7. 한계

- 이상 데이터가 다른 날 하루치 파일 하나(30 사이클, 약 2.7분)뿐이라, 다른 날짜·다른 고장 유형에
  이 판정 기준이 그대로 일반화된다고 보장할 수 없습니다.
- 10Hz 샘플링이라 원인 부품 단위까지 진단할 수 없고, 모양/크기 경보로 "전기·구동계 vs 기계계"
  정도의 큰 방향만 제시합니다.
- 센서 오류 예시는 실제 설비 데이터가 아니라 정상 데이터에 결함을 인위로 주입한 합성 샘플입니다.
- 정상 데이터 내장 샘플 전체에는 모델 학습에 쓰인 구간이 포함되어 있어("학습 데이터 포함, 성능
  평가용 아님"이라고 화면에 표시), 이 샘플의 결과를 모델 성능 지표로 해석하면 안 됩니다.
- 이상 확률(anomaly_prob) 보정기는 내장 이상 샘플 30개로 학습했기 때문에, 전혀 다른 양상의 새로운
  이상 신호에는 확률 값이 부정확할 수 있습니다(화면에 항상 고지).
